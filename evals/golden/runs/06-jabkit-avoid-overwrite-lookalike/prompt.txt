Number: 17458
Title: JabKit ignores --avoid-overwrite when generating citation keys
Body:
<<<ISSUE_BODY
When running JabKit's `citationkeys generate` with `--avoid-overwrite`, entries that already have a citation key still receive a newly generated key. The flag should leave those keys unchanged and generate keys only for entries that have none.

For example, an entry with `MyStableKey` becomes `Smith2024` in the output. If that output is used as the document's bibliography, existing references such as `\cite{MyStableKey}` no longer match.

### Steps to reproduce

1. Save this as `custom-key.bib`:

```bibtex
@Article{MyStableKey,
  author = {Smith, Alice},
  title = {Example study},
  journal = {Example Journal},
  year = {2024},
  month = jan,
}
```

2. Run:

```sh
jabkit citationkeys generate custom-key.bib --porcelain \
  --pattern '[auth][year]' --avoid-overwrite --output result.bib
```

3. Inspect the citation key in `result.bib`.

**Expected:** The output entry keeps `MyStableKey`.

**Actual:** The output entry has `Smith2024`, and the command exits with code `0`. The original input file remains unchanged; the issue is the existing key being replaced in the generated output despite `--avoid-overwrite`.

### Environment

JabKit portable development build `6.0-beta.190--2026-10-12--c8ddc2c`, macOS 26.5.2 ARM64. Tested with a disposable bibliography and isolated preferences.
