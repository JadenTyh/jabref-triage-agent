Title: Native JabKit RIS, CSV, and HTML exports fail and erase existing output files
Body:
<<<ISSUE_BODY
> Scope update: This issue now tracks missing native export layouts, addressed by #17416. Preserving existing files when a template export fails is tracked separately in #17423, following the maintainer's suggested split. The original reproduction is retained below.

### Description

I found that the native JabKit executable fails when exporting a bibliography to RIS, CSV, or HTML because it cannot find the required layout files.

More seriously, if the output file already exists, the failed export replaces it with an empty file. The command returns an error, but the previous contents are lost and no `.sav` backup remains.

I reproduced this using disposable files and compared the native executable with the portable Java distribution of the same version. All three exports succeeded with the Java distribution.

### JabRef version

Latest development branch build: `6.0-beta.142--2026-10-07--7415e00`.

Commit: `7415e005af647578025413da8dded1e6cd8f6657`.

### Operating system

macOS 26.5.2, ARM64.

I tested the official `jabkit-native_macos-silicon.zip` development build and compared it with the official `jabkit-portable_macos-silicon.zip`, using its bundled Amazon Corretto 25.0.4.1 Java runtime.

### Actual result

I used a small BibTeX file containing one article and exported it with `convert`, explicitly selecting `bibtex` as the input format and RIS, CSV, or HTML as the output format. Each destination already contained a disposable reference so I could check whether a failed export preserved its contents.

For RIS, the native executable reported:

```text
Failed to export file. (IOException: Cannot find layout file: '/resource/layout/ris/ris.layout'.)
```

The command exited with code `1`, and the existing RIS file shrank from 79 bytes to 0 bytes.

CSV export also exited with code `1`, reporting that `/resource/layout/csv/csv.layout` could not be found. Its existing output file shrank from 63 bytes to 0 bytes.

HTML export exited with code `1`, reporting that `/resource/layout/html.layout` could not be found. Its existing output file shrank from 67 bytes to 0 bytes.

No `.sav` backup remained after any of these failures.

### Expected result

The advertised built-in export formats should work in the native distribution. If an export fails, the existing output file should remain unchanged.

### Comparison and controls

I ran the identical input fixture through the portable Java distribution of the same version. RIS export succeeded with exit code `0` and produced a 97-byte file. CSV export succeeded with exit code `0` and produced a 417-byte file. HTML export succeeded with exit code `0` and produced a 1,758-byte file. All three generated files contained the expected reference.

BibTeX export succeeded in both distributions. As an additional control, I supplied an invalid output format: both distributions returned exit code `2` and preserved the existing output file unchanged.

The input bibliography remained unchanged throughout testing. These were actual executions of the downloaded binaries, using disposable fixtures; no existing bibliography was used or modified.

### Possible cause

The native failures indicate that the layout resources are unavailable in the packaged executable.

The output loss appears to be a separate error-handling problem: `TemplateExporter` opens an `AtomicFileWriter` before loading the required layout. When loading throws an exception, closing the writer still commits the empty temporary file instead of aborting the export.
